# 实现与复现技术说明

这份文件是 AI 生成的工程说明，供理解代码、复现实验和准备口头代码审查使用。它不是学生本人撰写的提交报告。

## 1. 为什么替换参考方案

参考程序用 64 个固定短语，每个短语占 6 位。这忽略了短语出现概率和上下文：无论 `the` 还是罕见标点，都使用同样的编码长度。固定短语也无法充分利用人名、词尾和反复出现的句式。

参考编码器不断执行 `data = data[len(s):]`，解码器不断执行 `indata = indata[3:]`，反复复制剩余文件，产生近似二次方的复制量。编码器还只写满四个编码的分组，丢弃最后不足四个的编码；参考解码器无条件补一个换行，只针对特定输入尾部工作。新实现使用顺序遍历、短历史和缓冲输出，并显式保存长度。

## 2. 状态和初始化

输入按原始字节处理，不做 Unicode 解码、换行转换、空白归一化或分词。这样所有空格、换行、标点和末尾内容都能精确恢复。

压缩文件保存按字节值升序排列的实际字符表。该文本字符表大小为 50。零阶模型是一个字典，每个字符的初始计数都是 1。其他模型最初不存在，第一次访问时建立空字典。字典的键是最多 K 个历史字节构成的上下文，值是“下一个字节 → 计数”的字典；默认 K=5。

非零阶字典保留首次出现符号的插入顺序，**不重新排序**。编码和解码在同样的时间插入符号，因此得到相同的累计频率顺序。这个顺序也是格式定义的一部分。Python 3.12 的字典保持插入顺序。

## 3. 对每个字节的预测

设当前历史为 `history`。构造上下文链：`history`、去掉首字节后的历史、继续去掉首字节，直到空字节串。开始时历史可能不足 K 字节，直接使用已有长度。

初始化排除集合 E 为空。从最长上下文往零阶模型尝试：

1. 空模型直接跳过。非空模型先排除 E 中的字符；若无剩余候选，也直接跳过。这些步骤不编码逃逸事件。
2. 候选字符 s 的整数权重为 `w(s)=2*c(s)-1`，其中 `c(s)` 是该上下文中计数。设候选数为 n，所有候选权重之和为 W。
3. 非零阶模型先编码“命中/逃逸”。命中时，在候选分布 `w(s)/W` 中编码字符，结束本字节的预测。
4. 逃逸时，将当前所有候选加入 E，转到下一阶。这是符号排除：低阶模型不再给已经证明无法命中的字符分配概率。
5. 零阶模型无需编码逃逸。因为它包含整个文件字符表，真实字符必然存在于其剩余候选中。

解码器按同样的步骤解码命中/逃逸和最终字符。它无需原文即可知道当前所有概率。

## 4. 自适应逃逸估计

逃逸概率并非对所有上下文固定。把统计特征相近的上下文放在一个共享估计桶中，桶的键依次为：

1. 当前上下文实际阶数。
2. 候选数桶：n<8 时直接用 n，否则用 `8+n.bit_length()`。
3. 平均候选权重的量级：`(W//n).bit_length()`。
4. 当前排除集合是否非空。

桶存储 `[H, X]`，分别表示命中和逃逸计数。第一次建立时设为 `[W,n]`，相当于以 PPM method D 的逃逸概率 `n/(W+n)` 初始化。此后使用概率 `H/(H+X)` 和 `X/(H+X)` 编码二元事件。

编码/解码事件后，将对应计数增加 1。当两项之和至少为 1024 时，将两项分别更新为 `(c+1)//2`，只执行一次。该规则使常用桶能适应文本变化，且保留正计数。大初值也严格按相同规则逐次缩放，不能在另一端改成不同的循环条件。

命中事件和命中后的字符分别调用区间编码器。不要把这套自适应逃逸概率误写成始终使用 method D 的固定逃逸概率。

## 5. 更新排除与模型缩放

成功恢复一个字符后，更新本次链中从最高阶到成功阶的模型，包括路径上的空模型：对该字符计数加 1，尚未存在时从 0 开始。低于成功阶的模型不更新；这称为更新排除。零阶模型因此并非全局字符频率直方图。

在某个更新后的模型中，如果该字符计数达到 4096，就把该模型所有字符计数改成 `(c+1)//2`。正计数不会消失。编码和解码必须在同一事件后执行缩放。

最后，把刚恢复的字符加入历史，仅保留末尾 K 字节。

## 6. 32 位字节区间编码

使用整数区间编码，初始 `range=0xffffffff`。一个事件的累计起点为 C、权重为 F、总权重为 T。编码步骤是：

```text
q = range // T
low = low + C*q
range = F*q
```

当 `range < 2^24` 时左移 8 位并输出一个确定字节。编码器的 `shift()` 使用缓存字节及待定 `0xff` 字节数处理进位；不能直接截断 `low` 的高位。结束时调用五次 `shift()`。

解码器读取五个初始字节（首字节必须为零），形成相对区间值 `code`。计算：

```text
q = range // T
target = code // q
```

选取满足 `C <= target < C+F` 的事件，然后令 `code -= C*q`、`range=F*q`。若区间不足 `2^24`，左移区间及 code，并读入下一个字节。所有运算都为整数，无浮点舍入差异。

这里的概率、整数取整、候选顺序、缓存进位和五字节终止规则共同定义码流，不能只凭相同的概率模型替换任意另一种算术编码器。

## 7. APM1 文件格式

所有多字节头字段采用小端序。固定头是 `struct.Struct("<4sBBHQII")`，总计 24 字节。

| 偏移 | 长度（字节） | 内容 |
|---:|---:|---|
| 0 | 4 | magic：ASCII `APM1` |
| 4 | 1 | 版本，当前为 1 |
| 5 | 1 | 最大上下文阶数 K，1–8 |
| 6 | 2 | 字符表大小，0–256 |
| 8 | 8 | 原始字节长度 |
| 16 | 4 | 区间编码数据长度 |
| 20 | 4 | 原始内容的 Adler-32 |
| 24 | 字符表大小 | 升序、无重复的字节字符表 |
| 24+字符表大小 | 数据长度 | 区间编码数据 |

Adler-32 从 `a=1,b=0` 开始，依次执行 `a=(a+s)%65521`、`b=(b+a)%65521`，最终值为 `(b<<16)|a`。这部分由 Python 整数实现，没有导入 `zlib`。

解码器拒绝错误标识/版本、无效阶数和字符表、文件长度不符、区间越界、数据截断、不规范终止及内容校验不符的输入。规范终止要求读取完整 payload 且最终 `code=0`。只有完整解码和校验成功后，才打开 `out.txt` 写入；损坏输入不会先覆盖已有输出。

该格式针对本项目大小设计，payload 长度字段为 32 位，没有实现任意大文件的流式接口。

## 8. 如何衡量效果

唯一需要评分的程序是 `decompress.py`。压缩器、测试和测量工具不进入评分大小，也不需要随解码器提交。

PDF 的目标值是 `len(compressed)+len(decompress.pyc)`。辅助指标包括总位数/原文字符数、用户 CPU 时间及峰值内存。`benchmark.py` 记录当前解释器版本，固定编译文件名为 `decompress.py`，使用正常编译选项，并把原文完全隔离在解码子进程之外。

gzip/bzip2/xz 的比较只计它们的压缩文件大小；本方案则同时给出计入解码器后的大小。这些标准压缩库只能在开发工具中使用，不能导入课程解码器。

时间复杂度取决于上下文分布；朴素候选扫描的上界约为 O(N*K*A)，A 为字符表大小。每个位置只复制最多 K 字节的历史，避免参考方案反复复制整份剩余文本。模型占用随不同上下文及其后继字符数量增长；实测内存见验证记录。
